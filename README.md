# 選定保存技術

[国指定文化財等データベース](https://kunishitei.bunka.go.jp/bsys/index) (文化庁) から抽出した**選定保存技術**のデータ。
1 行 1 件の JSON Lines です。

文化財分類コード 304 のデータです。文化財そのものではなく、**文化財を守るために欠かせない技術**  (修理・製作・原材料の生産など) が対象で、その保持者や保存団体が認定されます。

データは [heritage-crawler](https://github.com/shinyaoguri/heritage-crawler) が生成します。取得方法・スキーマの決定と
その根拠は、そのリポジトリの `docs/decisions/` にあります。

## 出典表記

```
出典：「国指定文化財等データベース」（文化庁）
（https://kunishitei.bunka.go.jp/）（YYYY年M月D日に利用）
上記を加工して作成
```

`YYYY年M月D日` は**利用日** (このデータをデータベースから取り出した日) です。
日付を埋めた表記が [`meta.json`](meta.json) の `source.attribution` にそのまま
入っているので、そこからコピーしてください。

利用条件は [LICENSE](LICENSE) を参照してください。**このリポジトリは画像を
含みません。**

## いつ時点のデータか

件数も日付も更新のたびに変わるので、この README には書きません。**正本はデータと
一緒に置いてあります。**

| 見る場所 | 中身 |
|---|---|
| [`meta.json`](meta.json) | `counts.records` = 収録件数 / `source.accessed_date` = **利用日** (データを取り出した日) |
| [`status.json`](status.json) | `checked_date` = **確認日** (変更が無いかを見にいった最後の日) |

**確認日が新しくて利用日が古いのは、上流が動いていないということです。**毎週見に
いっていますが、変更が無ければ取り出し直さないので利用日は動きません。逆に確認日が
何週間も止まっていたら、取得できていないと考えてください。

種別をまたいだ一覧は[閲覧サイト](https://code4heritage.github.io/heritages/)に
あります。

## データの形

```
data/99_unspecified.jsonl
```

- **1 行 1 件。** キーは `(台帳ID, 管理対象ID)` = `ledger_id` と `managed_id` の組
- 行は上記のキーで安定ソートしてあります (取得順の揺れを差分に出さないため)
- **ファイルは 1 つだけです。** この種別は所在地を持たないため
  (人や団体に結び付くもので、土地建物ではありません)、都道府県では分けられません。
  ファイル名の `99_unspecified` は「地域を定めない」の意味です
- **緯度経度もありません。**[閲覧サイト](https://code4heritage.github.io/heritages/)の
  地図には出ません
- 値が空の項目はキーごと落としてあります (`null` も空文字も出しません)
- 日付は ISO 8601 (`2004-11-08`)。和暦は西暦の言い換えなので落としています
- 項目の集合は文化財の種別によって異なります。1 行に必ずあるのは
  `ledger_id` / `managed_id` / `category_code` / `category_name` / `url` と
  `designation_kind` (この種別では `認定`)

`url` はデータベースの詳細ページを指します。原文と突き合わせるときはそこを見て
ください。項目の日本語の呼び名は [`meta.json`](meta.json) の `labels` にあります。

## 保持者・保持団体

**誰が認定されているかは `holders` に入っています。** 主情報には出てきません。

```json
"holders": [
  {"kind": "保持者", "name": "…", "name_kana": "…", "alias": "…", "date": "1955-03-19"},
  {"kind": "保持団体", "name": "…", "representative": "…", "date": "1993-04-15"}
]
```

`kind` は個人 (`保持者`) か団体 (`保持団体`) か。原文では欄の名前が個人と団体で
分かれていますが、意味が同じものは同じキーへ寄せてあります。

## 有形・無形の別

`types` は、その技術が何を守るためのものか (`有形` / `無形` / `有形・無形文化財等関係`)
を表します。文化財の種別ではありません。

## 更新

毎週月曜、データベースの台帳を取り直して差分を反映します。行が動いた週だけデータの
コミットが立ち、変更が無かった週は `status.json` の確認日だけが進みます。更新の差分が
そのまま「いつ何が変わったか」の履歴になります。ZIP と変更履歴は[リリース](https://github.com/code4heritage/selected-conservation-techniques/releases)に
あります。
